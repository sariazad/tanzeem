## 2-2 إدارة هويات الدخول والصلاحيات

| الضابط | التنفيذ | الحالة |
|---|---|---|
| التحقق من الهوية لكل وصول | جلسات على الخادم. مفاتيح API ورموز الأجهزة تُخزَّن تجزئاتها فقط | ✅ |
| التحقق متعدد العناصر للحسابات ذات الصلاحيات الهامة | TOTP، وإلزامي لمدير النظام افتراضياً، وقابل للتوسيع لأدوار أخرى | ✅ |
| مبدأ الحد الأدنى من الصلاحيات | RBAC لكل وحدة × إجراء، مع نطاق (جهة / فعالية). الأدوار الافتراضية مقيّدة | ✅ |
| مراجعة الصلاحيات دورياً | صفحة المستخدمين والأدوار + سجل التدقيق لكل تغيير | ✅ + 🏢 |
| سياسة كلمات المرور | 12 خانة، وثلاثة أنواع، وscrypt (N=16384) | ✅ |
| القفل بعد المحاولات الفاشلة | 5 محاولات، ثم قفل 15 دقيقة مع تنبيه | ✅ |
| إنهاء الجلسات | انتهاء بعد الخمول، وإنهاء فوري، وإجبار الخروج | ✅ |
| الربط بالهوية المركزية | Active Directory (LDAPS) والدخول الموحد OIDC (وSAML عبر وسيط) | ✅ ⚙️ |

## 2-15 أمن تطبيقات الويب (OWASP Top 10)

| البند | التنفيذ |
|---|---|
| A01 التحكم في الوصول | فحص الصلاحية والنطاق في كل مسار على الخادم، وليس في الواجهة فقط (اختبارات تكامل) |
| A02 الإخفاقات التشفيرية | راجع 2-8 |
| A03 الحقن | استعلامات SQL مُعدّة بمعاملات فقط، وأسماء الأعمدة من قائمة بيضاء، وهروب LDAP، ومنع حقن صيغ CSV وExcel، وكل النصوص في الواجهة عبر `textContent` |
| A04 التصميم غير الآمن | QR موقّع بلا بيانات، ومنع الدخول المزدوج، وتحقق الخادم من كل حقل |
| A05 سوء الإعداد | CSP صارمة (`script-src 'self'`) وX-Frame-Options وnosniff وReferrer-Policy وPermissions-Policy |
| A06 مكونات معرضة للثغرات | `npm audit` في CI. استبدال SheetJS على الخادم بكاتب مدمج |
| A07 فشل المصادقة | قفل، وTOTP، وكوكي HttpOnly + SameSite، وCSRF بترويسة مخصصة |
| A08 سلامة البيانات | Webhooks موقّعة HMAC، وتحقق توقيع OIDC (JWKS)، وPKCE |
| A09 التسجيل والمراقبة | راجع 2-12 |
| A10 SSRF | لا روابط من المستخدم يتبعها الخادم إلا روابط التكاملات التي يضبطها مدير النظام. SVG المرفوع يُفحص من السكربتات |
| حد المعدل | الدخول 15 في الدقيقة، والتحقق الثنائي 10، والربط 10، والتسجيل العام 20، وواجهة الـ API 3000 لكل IP في الدقيقة |
