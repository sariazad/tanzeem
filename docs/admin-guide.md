# دليل مدير النظام

## أول تشغيل

1. أنشئ حساب مدير النظام:
   ```sh
   node server/cli.js admin <email> "الاسم"
   ```
   في Docker: `docker compose exec app node server/cli.js admin …`
2. **الإعدادات ← الهوية البصرية:** الاسم والوصف والشعار والألوان والخط والتقويم. تُطبّق فوراً.
3. **الإعدادات ← قوالب الرسائل:** نص الدعوة والتذكير والتصريح بالعربية والإنجليزية.
4. **التكاملات:** البريد (SMTP) والرسائل النصية أولاً، ثم AD أو الدخول الموحد إن لزم. استخدم «اختبار الاتصال» بعد كل ضبط.
5. **المستخدمون والأدوار:** أنشئ الحسابات وأسند الأدوار بنطاقها.

## الأدوار والنطاق

**الأدوار الأساسية:** مدير النظام، إداري الجهة، منظم فعالية، استقبال/أمن، تقنية المعلومات، مشارك.
- يمكن تعديل صلاحياتها، عدا مدير النظام.
- يمكن إنشاء أدوار جديدة من مصفوفة (الوحدة × الإجراء).

**النطاق** يُحدَّد عند إسناد الدور:

| النطاق | المعنى |
|---|---|
| كل الجهات | دون قيود |
| جهة | الفعاليات والزيارات التابعة لها فقط |
| فعالية | فعالية واحدة. مناسب للمنظمين |

- يمكن إسناد أكثر من دور لنفس المستخدم بنطاقات مختلفة.
- **«الجلسات النشطة»:** إنهاء أي جلسة.
- **من قائمة المستخدم:** إجبار تسجيل الخروج، وفك القفل، وإعادة ضبط التحقق الثنائي.
- **الأمن ← التحقق الثنائي الإلزامي:** تحديد الأدوار المُلزمة به. الافتراضي مدير النظام.

## الأجهزة والأكشاك

### ربط الأجهزة

1. **الأجهزة ← جهاز جديد:** اختر النوع (كشك، طابعة بطاقات، جهاز استقبال، بوابة) والفعالية. يظهر **رمز ربط** من 6 أرقام، صالح 24 ساعة.
2. **الكشك:**
   - شغّل Chrome بملء الشاشة مع طباعة صامتة:
     ```
     chrome --kiosk --kiosk-printing https://<host>/kiosk
     ```
   - أدخل رمز الربط، واضبط الطابعة الافتراضية للنظام على طابعة البطاقات.
3. **طابعة Zebra:**
   ```sh
   node tools/print-agent/agent.mjs --server https://<host> --code <الرمز> --printer tcp://<IP>:9100
   ```
   - شغّله كخدمة: systemd على Linux، أو NSSM على Windows.
   - النص العربي في ZPL يتطلب خطاً عربياً TrueType محمّلاً على الطابعة. اضبط اسمه في إعداد `font` للجهاز.
   - البديل: طباعة المتصفح عبر تعريف الطابعة.

### الإدارة

- **صفحة الكشك:** الفعالية، والطابعة المرتبطة، ومهلة الخمول، والتسجيل الفوري، والتقاط الصورة، ووضع بوابة الخروج، ورسالة الترحيب.
  - تُرسل التغييرات للكشك لحظياً، مع معاينة حية.
- **الأوامر عن بعد:** إعادة تحميل، إعادة تشغيل، تحديث، تمييز الجهاز (وميض الشاشة)، مزامنة.
  - تصل فقط إذا كان الجهاز متصلاً.
- **التنبيهات التلقائية:** «جهاز منقطع» عند غياب النبضة دقيقتين، و«ورق منخفض» حسب حالة الطابعة.
- **سجل الأعطال وأوامر الطباعة:** في تفاصيل كل جهاز.

## التكاملات

| التكامل | الضبط |
|---|---|
| الدخول الموحد (OIDC) | Issuer وClient ID وSecret. عنوان العودة: `https://<host>/auth/oidc/callback`. SAML يتم عبر وسيط مثل Keycloak أو ADFS أو Azure AD |
| Active Directory | `ldaps://dc:636`، وBind DN لحساب خدمي بصلاحية قراءة، وBase DN، وفلتر المستخدم (الافتراضي `sAMAccountName`)، والدور الافتراضي للحسابات الجديدة |
| البريد | SMTP الجهة. بلا ضبط، تُسجَّل الرسائل فقط |
| الرسائل النصية | رابط مزوّد الرسائل وقالب الطلب (`{to}` و`{message}` و`{sender}`) ومفتاح API |
| التقويم | رابط ICS سري للاشتراك من Outlook أو Google |
| Webhooks | الرابط والأحداث. كل طلب موقّع: `X-Tanzeem-Signature: sha256=HMAC(secret, body)`، مع إعادة المحاولة بعد 1 و5 و30 و120 دقيقة |
| مفاتيح API | لكل مفتاح دور. يظهر مرة واحدة. يُرسل في الترويسة `X-API-Key` |
| الذكاء الاصطناعي | «المدمج» يعمل محلياً، أو نموذج متوافق مع OpenAI داخل الشبكة. يمكن تعطيل الوحدة من الإعدادات |

## النماذج وقوالب البطاقات

**النماذج:**
- أنواع الحقول: نص، بريد، جوال، رقم، تاريخ، قائمة، اختيار واحد أو متعدد، موافقة، صورة، رقم هوية.
- لكل حقل:
  - الإلزام.
  - صيغة التحقق (Regex).
  - حد أدنى وأعلى.
  - إظهار شرطي عند قيمة حقل آخر.
  - تسميات بالعربية والإنجليزية.

**البطاقات:**
- المقاسات: CR80 أفقي أو عمودي، وA6، وبطاقة 4×3 بوصة، أو مقاس مخصص.
- العناصر تُسحب وتُغيَّر أحجامها، والألوان قد تكون «حسب الفئة».
- أدوات: «طباعة تجريبية»، و«ZPL» لمعاينة أوامر Zebra.
- اجعل قالباً «افتراضياً» أو اربطه بفعالية من تعديلها.

## سجل التدقيق

- **ما يُسجَّل:** كل عملية، بالوقت والمنفذ وIP والقيم قبل وبعد، والقيم الحساسة محجوبة.
- **الحماية:** السجل لا يُعدَّل ولا يُحذف.
- **التحقق:** زر «التحقق من سلامة السجل» يتحقق من سلسلة التجزئة. من سطر الأوامر: `node server/cli.js verify-audit`.
- **التصدير:** CSV أو Excel.

## حماية البيانات

**الإعدادات ← حماية البيانات:** مدة الاحتفاظ ببيانات الزائر غير النشط (الافتراضي 730 يوماً).
- بعد المدة تُخفى الهوية تلقائياً كل 6 ساعات، وتبقى الإحصاءات.
- للتطبيق الفوري: `node server/cli.js retention`.
