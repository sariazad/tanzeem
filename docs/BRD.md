# وثيقة متطلبات الأعمال (BRD) — تنظيم

## 1. الهدف

منصة مؤسسية لإدارة الفعاليات والزيارات والزوار لجهة حكومية أو جامعة سعودية. تغطي الدورة كاملة:
1. الدعوة والتسجيل المسبق.
2. التحقق بالـ QR وتسجيل الدخول والخروج.
3. طباعة البطاقات من أكشاك الخدمة الذاتية.
4. التقارير والتحليلات اللحظية.

## 2. النطاق

**داخل النطاق:**
- الفعاليات بأنواعها الثلاثة: طلاب، ضيوف، رسمية.
- الزيارات والوفود.
- السجل الموحد للزوار، والمجموعات.
- التحقق والحضور: فردي، جماعي، ومن الكشك.
- البطاقات والأجهزة.
- التقارير والإشعارات والتكاملات.
- تطبيق الجوال بوضعي المنظم والمشارك.

**خارج النطاق في الإصدار 1.0:**
- الدفع وبيع التذاكر.
- البث المرئي.
- Apple/Google Wallet الأصلي.
- مزامنة التقويم ثنائية الاتجاه عبر Graph API.

## 3. أصحاب المصلحة والأدوار

| الدور | الاحتياج الرئيسي | النطاق الافتراضي |
|---|---|---|
| مدير النظام | التحكم الكامل والتدقيق والتكاملات | كل الجهات |
| إداري الجهة / العمادة | فعاليات جهته وزياراتها وتقاريرها | جهة |
| منظم فعالية | إدارة فعالية محددة وحضورها | فعالية |
| موظف استقبال / أمن | التحقق السريع والطباعة | كل الجهات أو جهة |
| فريق تقنية المعلومات | الأجهزة والتكاملات ومراقبة الحالة | كل الجهات |
| مشارك / زائر | تأكيد الدعوة واستلام رمز الدخول | بلا دخول للوحة؛ برابط الدعوة |

- الصلاحيات تُحدد لكل وحدة وإجراء: عرض، إنشاء، تعديل، حذف، تصدير، اعتماد.
- الأدوار تُنشأ وتُعدَّل من الواجهة.

## 6. معايير القبول

1. الصفحات الـ16 والصفحات الفرعية الخمس تعمل بالعربية والإنجليزية، وبالصلاحيات الصحيحة.
   - **التحقق:** E2E «الصفحات الـ16…» واختبارات الصلاحيات.
2. الرحلة الكاملة تعمل: إنشاء فعالية ← دعوة ← تأكيد ← QR ← دخول من الكشك مع طباعة ← ظهور لحظي في اللوحة والخريطة الحرارية ← خروج ← تقرير مُصدَّر.
   - **التحقق:** `tests/server.test.js` (الرحلة الكاملة) وE2E الكشك.
3. كل عملية تظهر في سجل التدقيق.
   - **التحقق:** الاختبار يتأكد من وجود الإجراءات، ومن سلامة السلسلة.
4. التشغيل يتم بأمر واحد، والاختبارات كلها تنجح.
   - **أمر التشغيل:** `docker compose up -d`، أو `sh install.sh`.
   - **التحقق:** على GitHub Actions.
